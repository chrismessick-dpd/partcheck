# Partcheck (partcheck): notes for Claude

Partcheck is the mechanical counterpart to Fabcheck. It's a static browser tool that opens a
mechanical fab package (STEP, drawing PDFs, DXF, BOM CSV) and shows:

- each part in 3D;
- its mass and size;
- package checks: do the files agree?
- draft and wall-thickness color maps.

It also exports previews and converts STEP to STL, OBJ, GLB or PNG. Read `README.md` first. Also
read `../CLAUDE.md`, which covers the suite's hard rules.

## Rules

- **No client data.** The demo is generated by `tools/make_demo.py` (the made-up Smart Thermostat,
  part numbers `2100410-…`). Never add real packages to `demo/` or the tests.
- **Client-side only.** Files are read in the tab and nothing is uploaded. The only network use is
  loading the pinned libraries from jsDelivr and cdnjs.
- **Libraries are pinned with SRI.**
  - The hashes are in `index.html` (JSZip, three.js) and in `assets/libs.js` (occt-import-js `.js`
    and `.wasm`, and pdf.js and its worker).
  - Changing a version means new hashes.
  - The CSP in `index.html` lists the allowed hosts.
- **OpenCascade runs in `assets/occt-worker.js`**, a same-origin worker. Its Emscripten glue uses
  `new Function`, which the page CSP blocks; a worker has its own (header) policy.
  - So STEP reading needs http(s), not `file://`.
  - Keep `'unsafe-eval'` out of the page CSP.
- **pdf.js renders with `intent: 'print'`.** The default paces rendering on animation frames, and
  those stop in a hidden tab or browser pane.
- **Findings never judge the design.** Package checks compare files with each other. Geometry
  analysis stays as views, with no pass/fail. Each check in `checks.js` `CATALOG` lists the Signoff
  ME check ids it supports (`related`); keep those ids real (`../me_design_review/templates`).
- **American English, metric first** ("1.2 mm (47.2 mil)"), using `PC.util.fmtLen` and the other
  `fmt*` helpers.
- `assets/suite.css` is copied from EE. Re-copy it with `python tools/sync_suite_css.py`, and never
  edit it here.

## Before finishing a change

1. Run `python tools/make_demo.py` if the generator changed. Then open `index.html?demo` and check
   that the planted findings are as expected (the list is in `tests/test.html`).
2. Run `python tools/stamp_version.py`.
3. Open `tests/test.html` over http. It should show PASS (18 tests as of 2026-11-01). The two demo
   tests need the network.
4. For a real-file check, use `samples/`. It's git-ignored and holds NIST's public-domain PMI test
   parts (AP242 STEP and their PDF drawings): `raw/` as NIST names them, and `named/` renamed to
   the `<pn>_<rev>_<desc>` convention. The source is
   https://www.nist.gov/document/nist-pmi-step-files. Expect a surface-body warning on all three.
   Don't put these files in `demo/`.

In the browser pane, scripts are cached: fetch changed files with `{cache: 'reload'}` before
reloading. The serve folder is `C:/Dovetail/tools` (preview `signoff-suite-alt`, port 8774).
